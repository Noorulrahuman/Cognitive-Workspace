4. PostgreSQL Schema & Hierarchy Architecture

Database structure implemented in supabase/schema.sql:

-- Stories table as child of projects
CREATE TABLE IF NOT EXISTS public.stories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID NOT NULL REFERENCES public.projects(id) ON DELETE CASCADE,
    title TEXT NOT NULL,
    description TEXT DEFAULT '',
    status TEXT NOT NULL DEFAULT 'todo' CHECK (status IN ('todo', 'in_progress', 'review', 'done')),
    priority TEXT NOT NULL DEFAULT 'medium' CHECK (priority IN ('low', 'medium', 'high', 'urgent')),
    due_date DATE,
    progress INTEGER NOT NULL DEFAULT 0 CHECK (progress >= 0 AND progress <= 100),
    created_at TIMESTAMPTZ NOT NULL DEFAULT timezone('utc'::text, now()),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT timezone('utc'::text, now())
);

-- Child link on tasks
ALTER TABLE public.tasks 
ADD COLUMN IF NOT EXISTS story_id UUID REFERENCES public.stories(id) ON DELETE CASCADE;

5. Global Cascade & Dual-Tier Progress Rollup

Global Story Cascade: When a user updates a Story's Due Date or Priority, updateWorkspaceStory automatically finds all child tasks where task.story_id === storyId and syncs the changes to both local cache and Supabase.
Dual-Tier Progress Rollup: Story completion is calculated using weighted task stages (done=100%, review=75%, in_progress=40%, todo=0%). Project completion computes 60% stories + 40% tasks.
